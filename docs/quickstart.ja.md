# Home Assistant スマートホーム · クイックスタート

> **ひとことで**：すでに自宅で動いている Home Assistant があり、本プラグインは「リビングの照明をつけて」といった言葉をその service 呼び出しに翻訳します。

---

## 1. 準備：アドレスとトークン

### Home Assistant のアドレスを確認する

普段使っている HA の Web UI を開き、アドレスバーを見ます：

- `http://homeassistant.local:8123`
- `http://192.168.1.50:8123`
- リバースプロキシやトンネル経由なら、そこで公開しているドメイン

**末尾のページパスを削除**し、`スキーム://ホスト:ポート` だけを残します。例：`http://192.168.1.50:8123/lovelace/0` → `http://192.168.1.50:8123`（プラグイン側でも一般的なフロントエンドパスは自動除去しますが、きれいに書いた方が確実です）。

### 長期アクセストークンを発行する

1. HA 画面の**左下のアバター**（旧版は右下）をクリック
2. **「セキュリティ」** タブを開く
3. 一番下の **「長期アクセストークン」** までスクロール
4. **「トークンを作成」** をクリックし、名前は任意（例：`N.E.K.O`）
5. 表示された `eyJ0eXAiOiJKV1Qi...` を**すぐにコピー** —— ダイアログを閉じると二度と見られません

> このトークンはアカウントの権限そのものです。プラグインは**暗号化して**保存します（Windows は DPAPI＝現在のユーザーとマシンに紐付け、それ以外は OS のキーチェーン）。どちらも使えない場合はメモリ上にのみ保持し、再起動後に再入力が必要です。**平文では絶対に保存しません。** 外部には末尾 4 文字だけを表示します。**チャット欄やスクリーンショットに貼らないでください。**

## 2. 接続する

1. N.E.K.O → プラグインパネル → **Home Assistant スマートホーム**
2. アドレスを確認 —— 既定で `http://127.0.0.1:8123` が入っています。HA が別のマシンならその IP に変更してください。続けてトークンを貼り付けます
3. **「接続テスト」** をクリック —— HA のバージョン、エンティティ数、管理者かどうかが表示されます
4. **「保存」** をクリック

続けて **「デバイスを更新」** を一度押すと、エンティティ一覧を取得します（以後 60 秒間はメモリキャッシュ）。

---

## 3. 声で操作する

AI パートナーにそのまま話しかけてください：

| やりたいこと | 言い方 |
| --- | --- |
| 電源 | `リビングの照明をつけて` / `書斎の照明を消して` |
| 明るさ | `リビングの照明を 40% にして` / `デスクライトを明るく` |
| 色温度 | `寝室の照明を 3000K` / `シーリングライトを暖かく` |
| エアコン | `エアコンを 26 度に` / `リビングのエアコンを冷房` / `エアコンの風量を自動` |
| カーテン | `カーテンを開けて` / `カーテンを半分開けて` |
| メディア | `スピーカーの音量 30` / `テレビをミュート` / `一時停止` |
| シーン | `帰宅シーンを実行` / `外出モードを発動` |

**言葉の理解は N.E.K.O の対話モデルが行い**、プラグイン自身はテキストを解析しません。「半分」「少し明るく」も通じます——モデルが `brightness: 50` に換算するか、具体的な数値を先に尋ねます。曖昧なほど質問が増えますが、デバイスを間違えるよりはましです。

## 4. デバイスが多すぎて見つからない？

照明が 3 つあるとき、`照明をつけて` は「複数一致」を返し、AI がどれか尋ねます：

```
「照明」に 3 件一致しました：
1. リビング シーリングライト（light.living_room_ceiling）
2. 寝室 シーリングライト（light.bedroom_ceiling）
3. 玄関 ダウンライト（light.hallway_downlight）
```

**プラグインが勝手に 1 つを選ぶことはありません**——一度尋ねるほうが、間違えるよりましだからです。対処は 3 つ：

- **詳しく言う**：`寝室のシーリングライトをつけて`（エリア名は HA の「エリア」設定に由来します）
- **別名を使う**：パネルで `light.yeelight_ceiling_2` を「メイン照明」など普段の呼び方に変更
- **エリアで言う**：`書斎の照明を全部消して`——AI がそのエリアの照明を先に列挙し、確認後に 1 台ずつ実行します

## 5. 安全確認

プラグインはリスクを 3 段階で管理し、**高リスク機器は既定では制御できません**：

| 段階 | 機器 | 既定 |
| --- | --- | --- |
| 低 | 照明・扇風機・メディア・シーン・通常のカーテン | 許可 |
| 中 | スイッチ／コンセント・空調 | 許可（パネルに表示） |
| 高 | スマートロック・セキュリティパネル・バルブ・給湯器・ガレージ／門 | **ブロック** |

高リスク機器はパネルで**1 台ずつ**有効化するしかありません（「ロックを一括選択」はありません）。有効化しても実行時に再確認が必要です——許可分は「制御してよいか」を決めるだけで、「確認を省く」ことにはなりません：

```
> 玄関のドアを開けて
< 高リスク操作のため未実行です。「玄関のスマートロック」に「解錠」を実行します。確認コード：a3f9c1d2（120 秒有効）

> a3f9c1d2
< 実行しました：lock.unlock — 状態を読み戻して unlocked を確認
```

コードは 1 回限り、「機器＋操作＋パラメータ」に紐付き、対象を変えると無効、120 秒で失効します。消灯・施錠・警戒など**世界を安全にする**方向は止めません。

## 6. Home Assistant を持っていない場合（体験モード）

**本プラグインは Home Assistant を同梱も代行インストールもしません。** これは意図的です：HA は独立したサービスであり、デバイス検出は HA が存在するネットワーク上で行う必要があり、サイズと更新頻度もプラグイン内には不適切です。

試したい場合の最短ルートは、常時稼働マシン（NAS／ミニ PC／ローカル機）での Docker です：

```bash
docker run -d \
  --name homeassistant \
  --restart=unless-stopped \
  --network=host \
  -v /path/to/ha-config:/config \
  ghcr.io/home-assistant/home-assistant:stable
```

`http://<そのマシンの IP>:8123` を開き、アカウントを作成して第 1 節の手順でトークンを発行します。実機がなくても、HA には `input_boolean` やテンプレートライトなどの仮想エンティティを追加できるので、動作確認には十分です。

> ⚠️ LAN 内デバイスの自動検出（特にブロードキャストに依存する Mijia/Tuya 系）には `--network=host` が必要です。ブリッジネットワークでは取りこぼします。

## 7. FAQ

**Q：「未設定」と表示される。**
A：接続が未保存です。アドレスとトークンを入れて「保存」を押してください。

**Q：接続テストが 401 / 403 で失敗する。**
A：トークンが誤っているか失効しています。HA の「セキュリティ」で再作成してください。403 は権限不足が多いです。

**Q：接続テストが繋がらない。**
A：プラグインは N.E.K.O のマシン上で動くので、**そのマシンから** HA に到達できる必要があります。まずそのマシンで `ping` するかブラウザで開いてみてください。`homeassistant.local` が解決できない場合は IP に変えてください。

**Q：操作はできるがエリア名が出てこない。**
A：WebSocket レジストリが読めていません（`get_status` に理由が出ます）。多くはトークンのユーザーが管理者でないためです。管理者アカウントでトークンを作り直してください。降格状態でもエンティティ名で照合できます。

**Q：追加したデバイスが出てこない。**
A：パネルの「デバイスを更新」を押してください。スナップショットは 60 秒キャッシュです。

**Q：ロボット掃除機／加湿器／スマートロックは？**
A：スマートロックは対応していますが高リスク扱いです。パネルで個別に有効化し、実行時には再確認が必要です。扇風機・バルブ・給湯器・セキュリティパネル・スクリプトも対応しています。ロボット掃除機・加湿器・カメラは未対応ですが、「未対応」と明示し、成功したふりはしません。センサーは制御できませんが**照会は可能**です。
