# Home Assistant 智慧家居 · 快速上手

> **一句話**：你家裡已經跑著一個 Home Assistant，本外掛負責把「打開客廳燈」這種話翻譯成它的 service 呼叫。

---

## 一、準備：取得位址與權杖

### 1. 找到你的 Home Assistant 位址

打開你平常使用的 HA 網頁，看瀏覽器網址列，形如：

- `http://homeassistant.local:8123`
- `http://192.168.1.50:8123`
- 走內網穿透／反向代理的話，是你映射出來的網域

把**結尾的頁面路徑去掉**，只留下 `協定://主機:連接埠`。例如 `http://192.168.1.50:8123/lovelace/0` → `http://192.168.1.50:8123`（外掛也會自動幫你剝掉常見前端路徑，但寫乾淨更省事）。

### 2. 建立長期存取權杖

1. 在 HA 頁面**右下角（新版在左下角）**點你的**頭像**
2. 切到 **「安全性」** 分頁
3. 拉到最底部的 **「長期存取權杖」**
4. 點 **「建立權杖」**，名稱隨意填（例如 `N.E.K.O`）
5. **立刻複製** 弹出的那串 `eyJ0eXAiOiJKV1Qi...` —— 關掉視窗就再也看不到了

> 這組權杖等同於你的帳號權限。外掛會把它存到 `plugins/homeassistant/data/credential.json`（原子寫入 + 權限收緊），對外只回顯末 4 碼。**不要**把它貼到聊天視窗或截圖裡。

---

## 二、連線

1. 打開 N.E.K.O → 外掛面板 → **Home Assistant 智慧家居**
2. 填入位址與權杖
3. 點 **「測試連線」** —— 通過後會顯示 HA 版本、實體數量、目前使用者是否為管理員
4. 點 **「儲存」**

建議順手點一下 **「重新整理裝置」**，讓外掛拉一遍實體清單（之後 60 秒內走記憶體快取）。

---

## 三、開始用嘴控制

直接對 AI 夥伴說：

| 你想做什麼 | 這麼說 |
| --- | --- |
| 開關燈 | `打開客廳吸頂燈` / `關掉書房燈` |
| 調亮度 | `客廳燈亮度調到 40%` / `檯燈亮一點` |
| 調色溫 | `臥室燈色溫 3000K` / `吸頂燈暖一點` |
| 空調 | `空調調到 26 度` / `客廳空調製冷` / `空調風速自動` |
| 窗簾 | `打開窗簾` / `窗簾開到一半` |
| 影音 | `音箱音量 30` / `電視靜音` / `暫停播放` |
| 場景 | `執行回家場景` / `觸發離家模式` |

**支援的說法比你想的多**：`一半` = 50%、`大半` = 70%、`最亮` / `最暗` / `最低` / `最高`、`調高一點` / `調低 10`、`26.5 度` 這種小數、`三千 K` 這種中文數字。

## 四、裝置太多找不到？

家裡有 3 個「燈」時，`打開燈` 會觸發消歧：

```
找到 3 個符合「燈」的裝置：
1. 🟢 客廳 吸頂燈
2. 🔴 臥室 吸頂燈
3. 🟢 玄關 筒燈
請用「區域名 + 裝置名」精確指定，例如「臥室吸頂燈」
```

兩個解法：

- **加區域名**：`打開臥室吸頂燈`（區域名來自 HA 的「區域」設定，不是你自己編的）
- **設別名**：在面板裡給實體設一個你習慣叫的名字，例如把 `light.yeelight_ceiling_2` 叫成「主燈」

## 五、安全確認

車庫門、大門、門鎖這類實體，外掛**不會直接執行**，而是給你一個 8 碼確認碼：

```
> 打開車庫門
< 即將執行「打開車庫門」，此操作有安全風險。確認碼：a3f9c1d2
  請在 120 秒內回覆該確認碼以繼續。

> a3f9c1d2
< 已執行：打開車庫門
```

確認碼只存在記憶體裡，**一次性使用**，只保留最新一筆，120 秒過期。宿主重啟即失效。

## 六、沒有 Home Assistant？（體驗模式）

**本外掛不含、也不代裝 Home Assistant。** 這是刻意的：HA 是獨立服務，裝置探索必須在 HA 所在的網路裡做，體積與更新節奏也不適合塞進外掛。

如果你想先試試，最快的路徑是在一台常開的機器（NAS／小主機／甚至本機）上用 Docker 跑一個：

```bash
docker run -d \
  --name homeassistant \
  --restart=unless-stopped \
  --network=host \
  -v /path/to/ha-config:/config \
  ghcr.io/home-assistant/home-assistant:stable
```

啟動後造訪 `http://<那台機器的IP>:8123`，建好帳號，再依第一節建立權杖。此時還沒有真實裝置也沒關係 —— HA 支援手動加入一些虛擬實體（例如 `input_boolean`、範本燈），足夠把外掛跑通。

> ⚠️ 用 `--network=host` 才能讓 HA 自動探索區域網路裝置（尤其米家／塗鴉這類依賴廣播的）。用橋接網路會漏裝置。

## 七、常見問題

**Q: 提示「未設定」？**
A: 還沒儲存過連線。填好位址與權杖，點「儲存」。

**Q: 測試連線失敗，回報 401 / 403？**
A: 權杖錯誤或已失效。去 HA 的「安全性」頁面重新建立。403 通常是該使用者權限不足。

**Q: 測試連線失敗，連不上？**
A: 外掛跑在 N.E.K.O 那台機器上，要**從那台機器**能存取到 HA 位址。先在那台機器上 `ping` 或用瀏覽器打開試試。用 `homeassistant.local` 解析不到的話，換成 IP。

**Q: 能控制裝置但叫不出區域名？**
A: 表示 WebSocket 登錄表讀不到（`get_status` 裡會顯示降級原因）。常見是權杖對應使用者不是管理員 —— 用管理員帳號建權杖即可。降級狀態下外掛仍能依實體名稱比對。

**Q: 新加的裝置沒出現？**
A: 面板點「重新整理裝置」。實體快照有 60 秒快取。

**Q: 支援掃地機／風扇／門鎖嗎？**
A: 目前聚焦六大基礎 domain（燈、開關、空調、窗簾、影音、場景）。其餘會明確告訴你「這個我還不支援」，不會假裝執行成功。
