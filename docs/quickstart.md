# Home Assistant 智能家居 · 快速上手

> **一句话**：你家里已经跑着一个 Home Assistant，本插件负责把「打开客厅灯」这种话翻译成它的 service 调用。

---

## 一、准备：拿到地址和令牌

### 1. 找到你的 Home Assistant 地址

打开你平时用的 HA 网页，看浏览器地址栏，形如：

- `http://homeassistant.local:8123`
- `http://192.168.1.50:8123`
- 走内网穿透/反代的话，是你映射出来的域名

把**末尾的页面路径去掉**，只留下 `协议://主机:端口`。比如 `http://192.168.1.50:8123/lovelace/0` → `http://192.168.1.50:8123`（插件也会自动帮你剥掉常见前端路径，但写干净更省事）。

### 2. 创建长期访问令牌

1. 在 HA 页面**右下角（新版在左下角）**点你的**头像**
2. 切到 **「安全」** 标签
3. 划到最底部的 **「长期访问令牌」**
4. 点 **「创建令牌」**，名字随便填（例如 `N.E.K.O`）
5. **立刻复制** 弹出的那串 `eyJ0eXAiOiJKV1Qi...` —— 关掉窗口就再也看不到了

> 这个令牌等同于你的账号权限。插件会把它存到 `plugins/homeassistant/data/credential.json`（原子写入 + 权限收紧），对外只回显尾 4 位。**不要**把它贴到聊天窗口或截图里。

---

## 二、连接

1. 打开 N.E.K.O → 插件面板 → **Home Assistant 智能家居**
2. 填入地址和令牌
3. 点 **「测试连接」** —— 通过后会显示 HA 版本、实体数量、当前用户是否管理员
4. 点 **「保存」**

建议顺手点一下 **「刷新设备」**，让插件拉一遍实体列表（之后 60 秒内走内存缓存）。

## 三、开始用嘴控制

直接对 AI 伙伴说：

| 你想做什么 | 这么说 |
| --- | --- |
| 开关灯 | `打开客厅吸顶灯` / `关掉书房灯` |
| 调亮度 | `客厅灯亮度调到 40%` / `台灯亮一点` |
| 调色温 | `卧室灯色温 3000K` / `吸顶灯暖一点` |
| 空调 | `空调调到 26 度` / `客厅空调制冷` / `空调风速自动` |
| 窗帘 | `打开窗帘` / `窗帘开到一半` |
| 影音 | `音箱音量 30` / `电视静音` / `暂停播放` |
| 场景 | `执行回家场景` / `触发离家模式` |

**支持的说法比你想的多**：`一半` = 50%、`大半` = 70%、`最亮` / `最暗` / `最低` / `最高`、`调高一点` / `调低 10`、`26.5 度` 这种小数、`三千 K` 这种中文数字。

## 四、设备太多找不到？

家里有 3 个「灯」时，`打开灯` 会触发消歧：

```
找到 3 个匹配「灯」的设备：
1. 🟢 客厅 吸顶灯
2. 🔴 卧室 吸顶灯
3. 🟢 玄关 筒灯
请用「区域名 + 设备名」精确指定，例如「卧室吸顶灯」
```

两个解法：

- **加区域名**：`打开卧室吸顶灯`（区域名来自 HA 的「区域」设置，不是你自己编的）
- **起别名**：在面板里给实体设一个你习惯叫的名字，比如把 `light.yeelight_ceiling_2` 叫成「主灯」

## 五、安全确认

车库门、大门、门锁这类实体，插件**不会直接执行**，而是给你一个 8 位确认码：

```
> 打开车库门
< 即将执行「打开车库门」，此操作有安全风险。确认码：a3f9c1d2
  请在 120 秒内回复该确认码以继续。

> a3f9c1d2
< 已执行：打开车库门
```

确认码只存在内存里，**一次性使用**，只保留最新一条，120 秒过期。宿主重启即失效。

## 六、没有 Home Assistant？（体验模式）

**本插件不含、也不代装 Home Assistant。** 这是刻意的：HA 是独立服务，设备发现必须在 HA 所在的网络里做，体积和更新节奏也不适合塞进插件。

如果你想先试试，最快的路子是在一台常开的机器（NAS / 小主机 / 甚至本机）上用 Docker 跑一个：

```bash
docker run -d \
  --name homeassistant \
  --restart=unless-stopped \
  --network=host \
  -v /path/to/ha-config:/config \
  ghcr.io/home-assistant/home-assistant:stable
```

启动后访问 `http://<那台机器的IP>:8123`，建好账号，再按第一节创建令牌。此时还没有真实设备也没关系 —— HA 支持手动添加一些虚拟实体（例如 `input_boolean`、`light` 模板灯），足够把插件跑通。

> ⚠️ 用 `--network=host` 才能让 HA 自动发现局域网设备（尤其米家/涂鸦这类依赖广播的）。用桥接网络会漏设备。

## 七、常见问题

**Q: 提示「未配置」？**
A: 还没保存过连接。填好地址和令牌，点「保存」。

**Q: 测试连接失败，报 401 / 403？**
A: 令牌错了或已失效。去 HA 的「安全」页面重新创建。403 通常是该用户权限不足。

**Q: 测试连接失败，连不上？**
A: 插件跑在 N.E.K.O 那台机器上，要**从那台机器**能访问到 HA 地址。先在那台机器上 `ping` 或浏览器打开试试。用 `homeassistant.local` 解析不到的话，换成 IP。

**Q: 能控制设备但叫不出区域名？**
A: 说明 WebSocket 注册表读不到（`get_status` 里会显示降级原因）。常见是令牌对应用户不是管理员 —— 用管理员账号建令牌即可。降级状态下插件仍能按实体名匹配。

**Q: 新加的设备没出现？**
A: 面板点「刷新设备」。实体快照有 60 秒缓存。

**Q: 支持扫地机 / 风扇 / 门锁吗？**
A: 目前聚焦六大基础 domain（灯、开关、空调、窗帘、影音、场景）。其余会明确告诉你「这个我还不支持」，不会假装执行成功。
