# Home Assistant 智能家居 · 快速上手

> **一句话**：你家里已经跑着一个 Home Assistant，本插件负责把「打开客厅灯」这种话翻译成它的 service 调用。

---

## 一、准备：拿到地址和令牌

### 1. 找到你的 Home Assistant 地址

打开你平时用的 HA 网页，看浏览器地址栏，形如：

- `http://homeassistant.local:8123`
- `http://192.168.1.50:8123`
- 走内网穿透/反代的话，是你映射出来的域名

把**末尾的页面路径去掉**，只留下 `协议://主机:端口`。比如 `http://192.168.1.50:8123/lovelace/0` → `http://192.168.1.50:8123`（插件也会自动帮你剥掉常见前端路径，但写干净更省事）。

### 2. 创建长期访问令牌

1. 在 HA 页面**右下角（新版在左下角）**点你的**头像**
2. 切到 **「安全」** 标签
3. 划到最底部的 **「长期访问令牌」**
4. 点 **「创建令牌」**，名字随便填（例如 `N.E.K.O`）
5. **立刻复制** 弹出的那串 `eyJ0eXAiOiJKV1Qi...` —— 关掉窗口就再也看不到了

> 这个令牌等同于你的账号权限。插件会把它**加密**保存在本机：Windows 用 DPAPI（绑定当前用户与机器），其他平台走系统钥匙串；两者都不可用时只留在内存里，重启需要重新填写——**绝不写明文**。对外只回显尾 4 位。**不要**把它贴到聊天窗口或截图里。

---

## 二、连接

1. 打开 N.E.K.O → 插件面板 → **Home Assistant 智能家居**
2. 填入地址和令牌
3. 点 **「测试连接」** —— 通过后会显示 HA 版本、实体数量、当前用户是否管理员
4. 点 **「保存」**

建议顺手点一下 **「刷新设备」**，让插件拉一遍实体列表（之后 60 秒内走内存缓存）。

---

## 三、开始用嘴控制

直接对 AI 伙伴说：

| 你想做什么 | 这么说 |
| --- | --- |
| 开关灯 | `打开客厅吸顶灯` / `关掉书房灯` |
| 调亮度 | `客厅灯亮度调到 40%` / `台灯亮一点` |
| 调色温 | `卧室灯色温 3000K` / `吸顶灯暖一点` |
| 空调 | `空调调到 26 度` / `客厅空调制冷` / `空调风速自动` |
| 窗帘 | `打开窗帘` / `窗帘开到一半` |
| 影音 | `音箱音量 30` / `电视静音` / `暂停播放` |
| 场景 | `执行回家场景` / `触发离家模式` |

**理解由 N.E.K.O 的对话模型完成**，插件本身不做中文分词。所以「一半」「亮一点」这类说法也能用——模型会把它折算成 `brightness: 50`，或先反问你具体数值。说法越模糊，模型越可能多问一句，但这比猜错设备好。

## 四、设备太多找不到？

家里有 3 个「灯」时，说 `打开灯` 会得到「匹配到多个」，由 AI 反问你要哪一个：

```
匹配到 3 个「灯」：
1. 客厅 吸顶灯（light.living_room_ceiling）
2. 卧室 吸顶灯（light.bedroom_ceiling）
3. 玄关 筒灯（light.hallway_downlight）
```

**插件不会替你挑一个**——它宁可多问一句，也不猜错设备。三个解法：

- **说全一点**：`打开卧室吸顶灯`（区域名来自 HA 的「区域」设置，不是你自己编的）
- **用别名**：在面板里给实体设一个你习惯叫的名字，比如把 `light.yeelight_ceiling_2` 叫成「主灯」
- **说区域**：`把书房的灯都关掉`——AI 会先列出该区域的灯，确认后再逐台下发

## 五、安全确认

插件按风险分三档管理权限，**高危设备默认完全不可控**：

| 档位 | 设备 | 默认 |
| --- | --- | --- |
| 低 | 灯、风扇、影音、场景、普通窗帘 | 允许 |
| 中 | 开关/插座、空调 | 允许（面板会标出来） |
| 高 | 门锁、报警面板、阀门、热水器、车库门/大门 | **阻止** |

高危设备只能在面板里**逐个勾选**，没有「整类一键全开」。勾选之后仍需二次确认——授权解决「能不能控」，不取消「确认了再控」：

```
> 把大门打开
< 这是高危动作，尚未执行。即将对「大门门锁」执行「解锁」。确认码：a3f9c1d2（120 秒内有效）

> a3f9c1d2
< 已执行：lock.unlock，回读状态确实变成了 unlocked
```

确认码一次性使用、绑定「设备 + 动作 + 参数」，换个目标即作废，120 秒过期。关灯、上锁、布防这类**让世界更安全**的方向不拦你。

## 六、没有 Home Assistant？（体验模式）

**本插件不含、也不代装 Home Assistant。** 这是刻意的：HA 是独立服务，设备发现必须在 HA 所在的网络里做，体积和更新节奏也不适合塞进插件。

如果你想先试试，最快的路子是在一台常开的机器（NAS / 小主机 / 甚至本机）上用 Docker 跑一个：

```bash
docker run -d \
  --name homeassistant \
  --restart=unless-stopped \
  --network=host \
  -v /path/to/ha-config:/config \
  ghcr.io/home-assistant/home-assistant:stable
```

启动后访问 `http://<那台机器的IP>:8123`，建好账号，再按第一节创建令牌。此时还没有真实设备也没关系 —— HA 支持手动添加一些虚拟实体（例如 `input_boolean`、`light` 模板灯），足够把插件跑通。

> ⚠️ 用 `--network=host` 才能让 HA 自动发现局域网设备（尤其米家/涂鸦这类依赖广播的）。用桥接网络会漏设备。

## 七、常见问题

**Q: 提示「未配置」？**
A: 还没保存过连接。填好地址和令牌，点「保存」。

**Q: 测试连接失败，报 401 / 403？**
A: 令牌错了或已失效。去 HA 的「安全」页面重新创建。403 通常是该用户权限不足。

**Q: 测试连接失败，连不上？**
A: 插件跑在 N.E.K.O 那台机器上，要**从那台机器**能访问到 HA 地址。先在那台机器上 `ping` 或浏览器打开试试。用 `homeassistant.local` 解析不到的话，换成 IP。

**Q: 能控制设备但叫不出区域名？**
A: 说明 WebSocket 注册表读不到（`get_status` 里会显示降级原因）。常见是令牌对应用户不是管理员 —— 用管理员账号建令牌即可。降级状态下插件仍能按实体名匹配。

**Q: 新加的设备没出现？**
A: 面板点「刷新设备」。实体快照有 60 秒缓存。

**Q: 支持扫地机 / 加湿器 / 门锁吗？**
A: 门锁支持，但属于高危设备——需要在面板里单独勾选授权，执行时还要过二次确认。风扇、阀门、热水器、报警面板、脚本也都支持。扫地机、加湿器、摄像头暂不支持控制，插件会明确说「这个我还不支持」而不是假装成功。传感器不能控制，但**可以查询**。
