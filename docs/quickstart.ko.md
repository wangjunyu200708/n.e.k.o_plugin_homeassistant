# Home Assistant 스마트 홈 · 빠른 시작

> **한 줄 요약**: 이미 집에서 Home Assistant를 운영 중이라면, 이 플러그인이 "거실 불 켜줘" 같은 말을 HA의 service 호출로 번역합니다.

---

## 1. 준비: 주소와 토큰

### Home Assistant 주소 확인

평소 쓰는 HA 웹 UI를 열고 주소창을 봅니다:

- `http://homeassistant.local:8123`
- `http://192.168.1.50:8123`
- 리버스 프록시/터널을 쓴다면 거기서 노출한 도메인

**끝의 페이지 경로를 제거**하고 `스킴://호스트:포트`만 남깁니다. 예: `http://192.168.1.50:8123/lovelace/0` → `http://192.168.1.50:8123` (플러그인이 흔한 프런트엔드 경로를 자동 제거하기도 하지만, 깔끔하게 적는 편이 안전합니다).

### 장기 액세스 토큰 발급

1. HA 화면 **왼쪽 아래 아바타** 클릭 (구버전은 오른쪽 아래)
2. **보안** 탭 열기
3. 맨 아래 **장기 액세스 토큰**으로 스크롤
4. **토큰 만들기** 클릭, 이름은 아무거나 (예: `N.E.K.O`)
5. 표시된 `eyJ0eXAiOiJKV1Qi...` 를 **즉시 복사** — 창을 닫으면 다시 볼 수 없습니다

> 이 토큰은 계정 권한과 같습니다. 플러그인은 **암호화하여** 저장합니다(Windows는 DPAPI로 현재 사용자·PC에 묶고, 그 외에는 시스템 키체인 사용). 둘 다 없으면 메모리에만 보관하며 재시작 후 다시 입력해야 합니다. **평문으로는 절대 저장하지 않습니다.** 외부에는 끝 4자리만 표시합니다. **채팅창이나 스크린샷에 붙여넣지 마세요.**

---

## 2. 연결

1. N.E.K.O → 플러그인 패널 → **Home Assistant 스마트 홈**
2. 주소 확인 — 기본값으로 `http://127.0.0.1:8123`이 채워져 있습니다. HA가 다른 PC에 있으면 해당 IP로 바꾸세요. 그다음 토큰을 붙여넣습니다
3. **연결 테스트** 클릭 — HA 버전, 엔티티 수, 관리자 여부가 표시됩니다
4. **저장** 클릭

이어서 **기기 새로고침**을 한 번 눌러 엔티티 목록을 가져오세요(이후 60초간 메모리 캐시).

## 3. 말로 제어하기

AI 파트너에게 그대로 말하면 됩니다:

| 하고 싶은 것 | 이렇게 말하세요 |
| --- | --- |
| 전원 | `거실 불 켜줘` / `서재 불 꺼줘` |
| 밝기 | `거실 불 밝기 40%` / `스탠드 조금 밝게` |
| 색온도 | `침실 불 색온도 3000K` / `천장등 좀 따뜻하게` |
| 에어컨 | `에어컨 26도로` / `거실 에어컨 냉방` / `에어컨 풍량 자동` |
| 커튼 | `커튼 열어줘` / `커튼 반만 열어줘` |
| 미디어 | `스피커 볼륨 30` / `TV 음소거` / `일시정지` |
| 장면 | `귀가 장면 실행` / `외출 모드 발동` |

**문장 이해는 N.E.K.O의 대화 모델이 담당하며**, 플러그인 자체는 텍스트를 해석하지 않습니다. "절반", "조금 밝게" 같은 표현도 됩니다 — 모델이 `brightness: 50`으로 환산하거나 먼저 구체적인 값을 묻습니다. 표현이 모호할수록 되묻는 일이 늘지만, 기기를 잘못 짚는 것보다 낫습니다.

## 4. 기기가 너무 많아 못 찾겠다면?

조명이 3개 있을 때 `조명 켜줘`라고 하면 "여러 개 일치"가 돌아오고, AI가 어느 것인지 되묻습니다:

```
"조명"에 3개가 일치합니다:
1. 거실 천장등 (light.living_room_ceiling)
2. 침실 천장등 (light.bedroom_ceiling)
3. 현관 다운라이트 (light.hallway_downlight)
```

**플러그인이 임의로 하나를 고르지 않습니다** — 한 번 묻는 편이 잘못 짚는 것보다 낫기 때문입니다. 해결책 세 가지:

- **더 자세히 말하기**: `침실 천장등 켜줘` (지역 이름은 HA의 '지역' 설정에서 옵니다)
- **별칭 사용**: 패널에서 `light.yeelight_ceiling_2`를 평소 부르는 이름으로 지정
- **지역으로 말하기**: `서재 조명 다 꺼줘` — AI가 해당 지역의 조명을 먼저 나열하고, 확인 후 하나씩 실행합니다

## 5. 안전 확인

플러그인은 위험도를 3단계로 관리하며 **고위험 기기는 기본적으로 제어할 수 없습니다**:

| 단계 | 기기 | 기본값 |
| --- | --- | --- |
| 낮음 | 조명, 선풍기, 미디어, 장면, 일반 커튼 | 허용 |
| 보통 | 스위치/콘센트, 공조 | 허용(패널에 표시) |
| 높음 | 도어락, 경비 패널, 밸브, 온수기, 차고문/대문 | **차단** |

고위험 기기는 패널에서 **하나씩** 허용해야 하며 "도어락 전체 선택"은 없습니다. 허용한 뒤에도 실행 시 2차 확인이 필요합니다 — 허용은 "제어해도 되는가"를 정할 뿐 "확인 없이 실행"을 뜻하지 않습니다:

```
> 대문 열어줘
< 고위험 동작이라 실행하지 않았습니다. "대문 도어락"에 "잠금 해제"를 실행합니다. 확인 코드: a3f9c1d2 (120초 유효)

> a3f9c1d2
< 실행했습니다: lock.unlock — 상태를 다시 읽어 unlocked 확인
```

코드는 1회용이며 "기기 + 동작 + 파라미터"에 묶여 있고, 대상을 바꾸면 무효가 되고 120초 후 만료됩니다. 소등·잠금·경계 설정처럼 **세상을 더 안전하게** 만드는 방향은 막지 않습니다.

## 6. Home Assistant가 없다면 (체험 모드)

**이 플러그인은 Home Assistant를 포함하지도, 대신 설치하지도 않습니다.** 의도된 설계입니다: HA는 독립 서비스이고, 기기 검색은 HA가 있는 네트워크에서 이루어져야 하며, 크기와 업데이트 주기도 플러그인에 넣기엔 부적합합니다.

가장 빠른 체험 방법은 상시 가동 머신(NAS/미니 PC/로컬 PC)에서 Docker로 띄우는 것입니다:

```bash
docker run -d \
  --name homeassistant \
  --restart=unless-stopped \
  --network=host \
  -v /path/to/ha-config:/config \
  ghcr.io/home-assistant/home-assistant:stable
```

`http://<그 머신 IP>:8123` 에 접속해 계정을 만들고 1절대로 토큰을 발급하세요. 실제 기기가 없어도 HA에 `input_boolean` 이나 템플릿 조명 같은 가상 엔티티를 추가할 수 있어 충분히 검증됩니다.

> ⚠️ LAN 기기 자동 검색(특히 브로드캐스트에 의존하는 Mijia/Tuya 계열)에는 `--network=host` 가 필요합니다. 브리지 네트워크에서는 누락됩니다.

## 7. FAQ

**Q: "설정되지 않음"이라고 나옵니다.**
A: 연결이 저장되지 않았습니다. 주소와 토큰을 입력하고 저장을 누르세요.

**Q: 연결 테스트가 401 / 403으로 실패합니다.**
A: 토큰이 틀렸거나 만료되었습니다. HA 보안 페이지에서 다시 만드세요. 403은 대개 권한 부족입니다.

**Q: 연결 테스트가 닿지 않습니다.**
A: 플러그인은 N.E.K.O 머신에서 실행되므로 **그 머신에서** HA에 접근 가능해야 합니다. 먼저 그 머신에서 `ping` 하거나 브라우저로 열어 보세요. `homeassistant.local` 이 해석되지 않으면 IP로 바꾸세요.

**Q: 제어는 되는데 영역명을 못 부릅니다.**
A: WebSocket 레지스트리를 못 읽은 상태입니다(`get_status`에 사유 표시). 대개 토큰 사용자가 관리자가 아니어서입니다. 관리자 계정으로 토큰을 다시 만드세요. 성능 저하 상태에서도 엔티티 이름으로 매칭은 됩니다.

**Q: 새로 추가한 기기가 안 보입니다.**
A: 패널에서 "기기 새로고침"을 누르세요. 스냅샷은 60초 캐시입니다.

**Q: 로봇청소기 / 가습기 / 도어락은 지원되나요?**
A: 도어락은 지원하지만 고위험 기기입니다. 패널에서 하나씩 허용해야 하고 실행 시 2차 확인이 필요합니다. 선풍기, 밸브, 온수기, 경비 패널, 스크립트도 지원합니다. 로봇청소기, 가습기, 카메라는 아직 제어할 수 없으며, 플러그인이 "지원하지 않는다"고 명확히 알려주고 성공한 척하지 않습니다. 센서는 제어할 수 없지만 **조회는 가능**합니다.
